00 解析設定の手順書：レーザー切断のアシストガス（reactingFoam・LTS）

作成日：2026-11-05　OpenFOAM v2512（ESI）

ノズルから吹き出す高圧ガス（N₂・O₂・空気）が、切断溝の中をどう流れ、周りの空気をどれだけ巻き込むかを計算するための手順書です。 ここでは「どのファイルの、どの行が肝か」と「なぜその値にしたか」をまとめます。 結果は 02・04、基礎式は 03、ソルバの選び方は 01 を見てください。

1. 全体の流れ（どのケースを元にすればよいか）

やりたいこと 元にするケース 作り方
まず傾向を早く見たい（数十分） run002_O2cut_mildSteel6mm（酸素切断）、run003_airCut_highPressure_t2mm（空気切断） tools/make_laser_case.py：軸対称（くさび形）、丸穴で溝を近似
溝の形（細長いスリット）と、切断の最前面を見たい（数時間） run004_kerf3D_N2_p*MPa tools/make_kerf3d_mix.py：3 次元、半分モデル（z = 0 が対称面）

作業の順番は次の 5 段階です。

  1. ケースを作る（Python スクリプトに寸法・圧力・ガスを渡す）
  2. メッシュを作る（Allrun の前半）
  3. 計算する（reactingFoam、4 並列）
  4. 収束を確かめる（残差・流量・局所時間刻み）
  5. 図を作る（tools/ の描画スクリプト）

1.1 どのチュートリアルを元にしたか

項目 元にしたもの 変えたところ
ソルバと時間の進め方（fvSchemes の localEuler、fvSolution の maxCo・alphaTemp・alphaY・Yref・rDeltaTSmoothingCoeff） $FOAM_TUTORIALS/combustion/reactingFoam/RAS/SandiaD_LTS（メタン火炎を LTS で定常にする例題） 燃焼をなくす、transonic yes を追加、maxCo を 0.15 → 0.2、物性を定比熱に、化学種を N₂・O₂ だけに

形状・メッシュ 例題は使わず、スクリプトで一から作成 軸対称：blockMesh のくさび。3 次元：blockMesh ＋ snappyHexMesh（ノズル・板は STL を自作）

4. 設定の肝（ここだけは理解してから変える）

4.1 ソルバ：reactingFoam を「燃焼なし・混合ガス」で使う

constant/thermophysicalProperties

thermoType
{
    type            hePsiThermo;        // 密度 = ψ p（圧縮性が強い流れ向け）
    mixture         reactingMixture;    // 複数の成分（N2, O2）を運ぶ
    transport       const;              // 粘性一定
    thermo          hConst;             // 比熱一定
    energy          sensibleEnthalpy;
    equationOfState perfectGas;
    specie          specie;
}

inertSpecie     N2;
  • hePsiThermo（密度 = ψ p）：圧縮性が強い流れ（超音速）向けです。圧力方程式を「波が伝わる式」として解けます。
  • reactingMixture：N₂ と O₂ を別々の成分として運び、混ざり具合（周りの空気の巻き込み）を計算します。
  • combustionProperties は none、chemistryProperties は chemistry off。反応は解きません。
  • hConst（比熱一定）と const（粘性一定）：超音速で膨張すると −150 ℃ 近くまで冷えます。JANAF の温度範囲（200 K〜）から外れて計算が壊れたため、定比熱を選びました。
    • N₂：cp 1040 J/(kg·K)
    • O₂：cp 918 J/(kg·K)
    • 値は constant/thermo.hConst にあります。

4.2 時間の進め方：LTS（局所時間刻み）で定常解を早く出す

system/fvSchemes

ddtSchemes
{
    default         localEuler;     // 局所時間刻み（LTS）
}

system/fvSolution の PIMPLE

PIMPLE
{
    momentumPredictor       yes;
    transonic               yes;    // 超音速・衝撃波を扱う圧力方程式にする（最重要）
    nOuterCorrectors        1;
    nCorrectors             2;
    nNonOrthogonalCorrectors 1;

    maxCo                   0.2;    // セルごとの Courant 数の上限。大きくすると速いが発散しやすい
    maxDeltaT               1e-6;
    rDeltaTSmoothingCoeff   0.02;   // 隣のセルとの時間刻みの差をならす
    rDeltaTDampingCoeff     1;
    alphaTemp               0.05;   // 温度が 1 回で大きく変わらないように時間刻みを抑える
    alphaY                  0.05;   // 成分の割合についても同じ
    Yref
    {
        O2                  0.1;
    }
}
  • localEuler は、セルごとに許される一番大きな時間刻みで進めます。時間の正確さを捨てて、定常の答えに早く近づける方法です。そのため endTime は「反復回数」として読みます。
  • transonic yes がないと、ノズル出口のチョーク（音速で詰まる）や衝撃波が出ません。 超音速の計算では必ず入れます。

4.3 境界条件：入口は「全圧」、出口は「大気圧で出入り自由」

境界 p U T O₂ / N₂
inlet（ノズル入口） uniformTotalPressure（全圧を 500 回かけて大気圧→設定圧に上げる） pressureInletOutletVelocity totalTemperature（300 K） 指定したガス（N₂ なら O₂ = 0）
top・bottom・ambient（周り） totalPressure（大気圧） pressureInletOutletVelocity inletOutlet 300 K inletOutlet（入ってくるのは空気：O₂ 0.233）
nozzle・plate（壁） zeroGradient noSlip zeroGradient（断熱） zeroGradient
symmetryPlane（3D の z = 0） 対称 対称 対称 対称
  • 入口の圧力は一気に上げない：p0 table ((0 101325) (500 2101325) (1e9 2101325)) のように、最初の 500 回で上げます。いきなり高圧にすると初回で発散します。
  • 流量ではなく圧力で与える：実機の設定値はガス圧なので、これがそのまま入力になります。流量は結果として出てきます（理論値との比較は 5 章）。
  • 周りの境界はガスが逆流しても空気が入るようにする：inletOutlet にしておくと、巻き込まれる空気の O₂ を正しく運べます。

4.4 メッシュ：溝とすき間だけ細かく

system/snappyHexMeshDict の refinementRegions

領域 細かさ（背景 0.5 mm に対して） セルの大きさ
slot（切断溝の中） レベル 4 約 0.03 mm（溝幅 0.3 mm に 約 10 セル）
jet（ノズルの真下の円柱） レベル 3 約 0.06 mm
gap（ノズルと板のすき間） レベル 2 約 0.125 mm
板の表面 レベル 3〜4 —

溝の幅に 10 セル程度ないと、溝の中の速度分布が出ません。メッシュを粗くして時間を短くしたい場合は、slot を最後に粗くします。

constant/turbulenceProperties：realizableKE（3D）、kOmegaSST（軸対称）。壁は壁関数です。

入口の値：

  • 乱れの強さ：5 %
  • 混合長：0.1 mm（ノズル径の 1 割弱）

5. 手順 4：収束の確かめ方（3 つ全部見る）

何を見るか どこにあるか 合格の目安
ノズル流量 postProcessing/inletFlow/0/surfaceFieldValue.dat（20 回ごと） 最後の 1,000 回で変化が 1 % 以内
溝の下を抜ける流量 postProcessing/slotFlow/0/... 同上
局所時間刻み log.reactingFoam の deltaT = min max 最小値が 10⁻⁹ s 程度より大きいまま
残差 python3 tools/plot_residuals.py res.png <ケース> 10⁻³〜10⁻⁴ で横ばい（LTS では下がりきらない）

ノズル流量は、一次元の理論（チョーク流）とも比べます。2 割以内なら妥当です。

\[\dot m = A\,p_0\sqrt{\frac{\gamma}{R T_0}}\left(\frac{2}{\gamma+1}\right)^{\frac{\gamma+1}{2(\gamma-1)}}\]

  • A：ノズル出口の面積、p0：供給圧（絶対圧）、T0：供給温度
  • γ = 1.4、R = 296.8 J/(kg·K)（N₂）
  • 3D は半分モデルなので、出てきた流量を 2 倍して比べます。

6. つまずきやすい点（実際に起きたこと）

症状 原因 対策
局所時間刻みの最小値が 10⁻¹² s 台まで落ち、計算が進まなくなる 超音速の噴流が、勢いを保ったまま圧力境界にぶつかる。境界の手前で真空に近いセルができる 計算領域を広げる。板の下は 10 mm、横（x・z）は ±10 mm にした（0.5・2.0 MPa は解決）
4.0・8.0 MPa だけ止まる 高圧ほど噴流が遠くまで届く。±10 mm でもまだ足りない可能性がある 未解決。領域をさらに広げる、maxCo を下げる、圧力を上げる回数を増やす、を検討中
低温で物性エラー JANAF の温度範囲外（200 K 未満） hConst にする（4.1）
圧力の表を書き換えても効かない p0Coeffs の古い指定が残っていて優先された 0/p の入口から p0Coeffs を消す
mpirun が返ってこない（WSL2） hwloc が画面の情報を取りに行って止まる export HWLOC_COMPONENTS=-gl

9.3 YAML の書き方

case: ../run_example_twoInlets        # 作るケースのフォルダ（この YAML からの相対パス）

mesh:
  type: blockMesh                     # blockMesh | snappyHexMesh | polyMesh | fluent | gmsh | unv
  blockMeshDict: blockMeshDict        # snappyHexMesh / polyMesh は dir:、fluent / gmsh / unv は file:
  scale: 1.0                          # CAD のメッシュが mm なら 0.001

gases: [N2, O2]                       # 使えるガス：N2, O2, Ar, CO2, He, H2O

ambient:                              # 最初の状態と、出口から逆流して入ってくるガス
  p: 101325
  T: 300
  composition: {N2: 79, O2: 21}
  basis: mole                         # mole（モル %、体積 % と同じ）か mass（質量 %）

boundaries:                           # メッシュの境界名（正規表現も可）→ 条件
  inlet1:
    type: inlet
    p_total_gauge: 0.2e6              # 供給圧（ゲージ圧 Pa）。p_total（絶対圧）か mass_flow（kg/s）でもよい
    T_total: 300
    composition: {N2: 100}            # N2 100 %
  inlet2:
    type: inlet
    p_total_gauge: 0.02e6
    composition: {O2: 90, N2: 10}     # O2 90 %、N2 10 %（モル %）
  outletEnd:
    type: outlet
    p: 101325
    pressure_type: static             # 噴流が抜ける出口：静圧を固定
  outletTop:
    type: outlet
    pressure_type: total              # 周りの空気が吸い込まれる開口：全圧を固定（既定）
  axis:
    type: symmetryPlane               # symmetryPlane | symmetry | wedge（軸対称）| empty（2 次元）
  frontBack:
    type: empty

default: wall                         # 上に書かなかった境界はすべて断熱の壁
# 温度を固定した壁：  myWall: {type: wall, T: 350}

turbulence:
  model: realizableKE                 # realizableKE | kEpsilon | kOmegaSST | laminar

solver:
  iterations: 3000                    # LTS の反復回数
  write_interval: 1000
  maxCo: 0.2
  pressure_ramp_iterations: 500       # 入口の圧力をこの回数かけて上げる
  T_limits: [50, 3000]                # 温度の上下限（limitTemperature）

parallel: 2                           # 並列数（1 なら並列なし）

YAML の各項目が、OpenFOAM の何になるか

YAML OpenFOAM の設定
type: inlet ＋ p_total_gauge p：uniformTotalPressure（psi・gamma 付きの圧縮性の全圧、pressure_ramp_iterations 回で上げる）、U：pressureInletOutletVelocity、T：totalTemperature
type: inlet ＋ mass_flow U：flowRateInletVelocity（massFlowRate）、p：zeroGradient、T：fixedValue
composition ＋ basis 各ガスの fixedValue（モル % は分子量で質量分率に直す）
type: outlet p：totalPressure（pressure_type: static なら fixedValue）。U は pressureInletOutletVelocity、T とガスは inletOutlet（逆流は ambient か composition_backflow のガス）
type: wall U：noSlip、T：zeroGradient（断熱）か fixedValue、乱流は壁関数。メッシュの境界の種類も wall に書き換える
symmetryPlane など 全部の場で同じ種類にし、メッシュの境界の種類も書き換える
solver・turbulence 4 章の設定（localEuler、transonic yes、maxCo、定比熱の混合ガス）をそのまま使う

9.4 例題の結果（2 次元、11,850 セル、2 並列で約 3 分）

  • 先細りのノズル（左下）から N₂ が出ます（0.2 MPa ゲージ）。音速を超えて、衝撃波のセルが並んでいます（左図）。
  • 上の入口から O₂ 90 % のガスがゆっくり流れ、主噴流に巻き込まれて混ざります（右図）。
  • ノズル流量は 0.76 g/s（奥行き 1 mm あたり）です。一次元の理論値 0.69 g/s より約 10 % 多くなりました。

9.5 条件を決めるときの注意（例題で実際につまずいたこと）

注意 理由
圧力で与える入口は、流れの遅いところ（ノズルの上流の太い部分）に置く 入口のすぐ先で超音速になる形だと、入口から入る流量が決まらない。最初の例題ではノズルなしの開口を入口にしたため、理論の何倍もの流量になり、温度・圧力が壊れた
圧力の低い入口を、圧力の高い噴流のすぐそばに置かない 噴流がぶつかって圧力が上がり、低圧の入口から逆に流れ出す（逆流）。その入口に totalTemperature が付いていると、温度が壊れやすい
噴流が抜ける出口は pressure_type: static、周りの空気を吸う開口は total 噴流が全圧固定の境界にぶつかると、真空に近いセルができて計算が止まる（6 章と同じ現象）
出口の流量は揺れてもよい。入口の流量が落ち着いたかで収束を判断する 2 次元の噴流は渦が出て、出口の流量が揺れ続ける
2 次元は前後の面を empty、軸対称は wedge と YAML に書く 書かないと default: wall で壁になる
書かなかった境界はすべて壁になる blockMesh で面を指定しなかったところ（defaultFaces）も壁になる
