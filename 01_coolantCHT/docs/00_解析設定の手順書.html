00 解析設定の手順書：加工エリアのクーラントと熱（chtMultiRegionTwoPhaseEulerFoam）

作成日：2026-11-05　OpenFOAM v2512（ESI）

加工エリアの天井のノズルから温かいクーラントがワークにかかり、テーブルとワーク（固体）が温まる様子を計算する手順書です。 流体は空気とクーラントの二相（オイラー–オイラー法）として解き、固体の熱伝導を同時に解きます。 この手順書では次の 3 点をまとめます。

  • どのチュートリアルから持ってきたか
  • どこを書き換えたか
  • 設定の肝

ソルバの式は 01、結果は 02、VOF との違いは 03 を見てください。

1. 元にしたチュートリアル

項目 内容

実際の場所（この PC） /usr/lib/openfoam/openfoam2512/tutorials/heatTransfer/chtMultiRegionTwoPhaseEulerFoam/solidQuenching2D

例題をそのまま試すときは、例題のフォルダを丸ごとコピーして ./Allrun を実行します（中身は Allrun.pre → ソルバ）。

変数 意味 値

手順 2：メッシュを作って計算する

4. 設定の肝

4.1 領域の分け方：regionProperties

regions
(
    fluid       (water)     // 流体領域（空気とクーラントの 2 相）
    solid       (solid)     // 固体領域（テーブル＋ワーク）
);
  • 流体領域の名前は water です。中に「空気（gas）」と「クーラント（liquid）」の 2 相が入っています。
  • 固体領域は solid で、テーブルとワークを 1 つにまとめています。接触熱抵抗はありません。
  • 設定ファイルも領域ごとに分かれます：system/water/、system/solid/、constant/water/、constant/solid/、0.orig/water/、0.orig/solid/。

4.2 二相の扱い：constant/water/phaseProperties

設定 値 意味
type thermalPhaseChangeTwoPhaseSystem 2 つの相それぞれに速度・温度を持たせる（オイラー–オイラー法）
phaseChange off 蒸発・沸騰はしない（35 ℃ なので不要）
液の diameterModel constant、d 0.00045 空気中に散ったクーラントを直径 0.45 mm の滴として扱う
drag IshiiZuber 相の間の抵抗
blending 割合 0.3〜0.7 で切り替え 「空気の中の滴」と「液の中の泡」を、割合によってなめらかにつなぐ

肝：オイラー–オイラー法は、液面（水と空気の境目）をくっきりとは描けません。液がどのあたりにどれだけあるか（割合）を求める方法です。液面の形そのものが大事な場合は VOF を使います（03 を参照）。

4.3 流体と固体の熱のやりとり（最重要）

流体側 0.orig/water/T.liquid の water_to_solid

type        compressible::turbulentTemperatureTwoPhaseRadCoupledMixed;
Tnbr        T;              // 相手（固体）の温度の場の名前
kappaMethod phaseSystem;
region      fluid;
otherPhase  gas;            // 同じ流体領域のもう一つの相

固体側 0.orig/solid/T の solid_to_water

type        compressible::turbulentTemperatureTwoPhaseRadCoupledMixed;
Tnbr        T.liquid;       // 相手（流体）の液の温度
kappaMethod solidThermo;
region      solid;
otherPhase  gas;
  • 液と空気が両方触れている壁でも、それぞれの割合に応じて熱を受け渡します。
  • 気相の温度 T.gas の壁の条件は copiedFixedValue（T.liquid の値を写す）。
  • 液の壁の乱流熱拡散 alphat.liquid の water_to_solid は alphatWallBoilingWallFunction（例題のまま）。沸騰しない温度では、ふつうの壁関数と同じように働きます。

4.4 入口と出口の条件（make_case.py で追加）

境界 液の割合 速度（液・気） 温度 圧力 p_rgh
inlet（天井のノズル 40 × 40 mm） alpha.liquid = 1（液だけ） 下向き 1.0 m/s 308 K fixedFluxPressure
drain（床の左右の帯 x < 100、x > 500 mm） 出入り自由（入るのは空気） pressureInletOutletVelocity inletOutlet prghTotalPressure（大気圧）
maxY（天井のノズル以外＝換気口） 例題のまま（入るのは空気） pressureInletOutletVelocity inletOutlet 293 K prghTotalPressure
maxX（囲いの側面）・minY（床） — 止まっている壁 293 K 一定 fixedFluxPressure

肝：排出口がないと、加工エリアに液がたまり続けて計算が崩れます。必ず液が出られる境界（drain）を作ります。

4.5 時間刻みと解き方

system/controlDict

adjustTimeStep  yes;
maxCo           0.5;        // Courant 数の上限
maxDi           10.0;       // 拡散数の上限（固体の熱伝導）
maxDeltaT       2e-3;       // 時間刻みの上限 [s]
  • 時間刻みは Courant 数 0.5 に合わせて自動で決まります。噴流が速いところで刻みが小さくなります。
  • system/water/fvSolution の PIMPLE（nOuterCorrectors 2、nEnergyCorrectors 4、faceMomentum yes）は例題のままです。二相流で安定させる設定なので、まず変えないでください。
  • constant/water/fvOptions の limitTemperature（300〜2000 K）は例題のままです。下限 300 K（27 ℃）が室温 293 K より高いので、流体の温度は 27 ℃ 未満にはなりません。室温付近の流体の温度を細かく見たい場合は、下限を 273 K などに下げてください。

4.6 熱伝達率の出力（例題のまま使える便利機能）

system/controlDict の functions

  • htc（reactingEulerHtcModel）：壁 water_to_solid の熱伝達率を、基準温度 TRef 373 K で計算します。
  • htcSurfaceFieldValue：その面平均をログと postProcessing/ に出します。

基準温度は沸騰の例題に合わせた 373 K のままです。クーラントの温度で評価したい場合は TRef を 308 にします。
